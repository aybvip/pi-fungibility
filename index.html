π = π — Is Pi on exchanges the same as mined Pi?

Answer: yes — and it is deterministic, not a loophole.

Canonical claim: A native Pi payment carries no observable per-unit mining origin on the Pi Mainnet ledger.

π mined in the Pi app, π withdrawn from an exchange (OKX / Bitget), and π sent from inside a Pi Browser app are the same native asset. On-chain, every π is identical: the native asset has no issuer and no contract, and the ledger records balances — not “coins” tagged with an origin.

mined π = π from OKX/Bitget = π from inside a Pi Browser app

The proof, layer by layer

LayerWhat it showsOrigin field?
1 — Blockchain (Horizon)Pi is a Stellar-protocol chain; the native asset has no asset_issuer; a balance is one scalarNo
2 — Pi Wallet SDK (window.Pi)createPayment accepts only amount / memo / metadata; transactions are plain native paymentsNo
3 — Platform API (PaymentDTO)identifier, user_uid, amount, memo, metadata, from_address, to_address, direction, created_at, network, status, transaction.txidNo
4 — Soroban smart contractsThe contract-facing token interface exposes only scalars: balance, allowance, transfer, transfer_from, approveNo

Because Pi uses an Account/Balance model (not UTXO), the history → state map is non-injective: after the first merge into a wallet the per-unit trail is gone. Account-level transaction-graph analysis is possible (you can label addresses), but unit-level provenance is undefined.
